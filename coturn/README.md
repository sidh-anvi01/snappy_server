# coturn for SnappY video calls

This config runs coturn on a Linux VPS with a public IPv4 address. It uses
time-limited credentials generated by the backend's `/api/v1/call/ice-servers`
endpoint.

## 1. Prepare the VPS

Use an Ubuntu VPS with a stable public IP. Point a DNS name such as
`turn.example.com` at that IP. Install Docker Engine and the Docker Compose
plugin using Docker's official installation instructions.

Open these ports in both the VPS firewall and the provider's cloud firewall:

- `3478/udp` and `3478/tcp` for TURN
- `49160-49200/udp` for relayed media

For UFW, the matching commands are:

```sh
sudo ufw allow 3478/udp
sudo ufw allow 3478/tcp
sudo ufw allow 49160:49200/udp
```

The compose file uses host networking, which is recommended for coturn's
relayed UDP port range.

## 2. Configure the shared secret

Set these variables on the backend host. For local development, put them in
the backend `.env`; for Render, add them in the web service's Environment
settings:

```env
TURN_REALM=turn.example.com
TURN_URLS=turn:turn.example.com:3478?transport=udp,turn:turn.example.com:3478?transport=tcp
TURN_SECRET=<a-long-random-secret>
```

Generate a secret on the VPS with `openssl rand -hex 32`. Keep it private and
use the exact same value in the backend's environment and the coturn deployment.
Do not put it in the mobile app or commit it to source control.

## 3. Start coturn

The coturn VPS needs a local `.env` file with `TURN_REALM` and `TURN_SECRET`
for Docker Compose. From the backend directory on that VPS, run:

```sh
docker compose --env-file .env -f coturn/compose.yaml up -d
docker compose --env-file .env -f coturn/compose.yaml logs
```

The compose file enables coturn's shared-secret authentication, matching the
temporary credentials generated by `controllers/callController.js`.

## 4. Deploy and test

For Render, deploy the backend as a persistent Node.js Web Service using
`npm install` as the build command and `npm start` as the start command. Set
`JWT_SECRET_KEY`, `MONGODB_URI`, `TURN_REALM`, `TURN_URLS`, and `TURN_SECRET` in
the Render Environment settings. Keep a single service instance because call
signaling state is held in process memory.

Set the mobile app's `BASE_URL` in `SnappY/Src/config/Config.js` to the
deployed Render HTTPS URL before building a release. The current Android
emulator URL (`10.0.2.2`) is only for local development.

Restart/redeploy the backend after setting its environment. Check that an
authenticated request to `/api/v1/call/ice-servers` returns the Google STUN
entry and a TURN entry with a temporary `username` and `credential`. Do not
log or share the credential response.

Make calls between devices on different networks, for example Wi-Fi and
cellular. For a test build, add `iceTransportPolicy: 'relay'` to the
`RTCPeerConnection` configuration to confirm TURN relay works, then remove it
for normal use.

This setup does not enable TURN over TLS. Add a TLS certificate and configure
coturn's certificate/private-key options before advertising a `turns:` URL.
The signaling backend must also run as a persistent Node.js service; this
project keeps active call state and Socket.IO connections in process memory,
which is not suitable for a serverless deployment.
